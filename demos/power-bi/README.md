## Local preparation

1. Copy `config.example.json` to a local config within this directory; verify resource IDs and set `parent_catalog_approved: true` to record the existing approval for `dbxfabricinterop`. Defaults: Databricks workspace/catalog `dbxfabricinterop`, prefix `fabricinterop`, schema/workspace `fabricinterop_powerbi`, DirectQuery, OAuth, timeout 900 seconds, 365/20/100/10000 rows, seed 42. A custom prefix requires updating all corresponding names explicitly. Import requires both `storage_mode: "Import"` and `import_explicitly_approved: true`; never silently switch modes. Set actual names/IDs only after independent verification. Keep secrets out.
2. From the repository root, run `python demos\power-bi\prepare.py --config demos\power-bi\config.local.json --output demos\power-bi\prepared`. The output directory must not already exist. The script runs locally only, checks catalog approval, generates four deterministic datasets via `demos.common.star_schema`, validates PK/FK integrity independently and emits:
   * `01-create-and-load.sql`: CREATE schema, four constrained Delta tables and deterministic inserts, **not idempotent**.
   * `02-check-and-reference.sql`: independent data-integrity checks, `SHOW CREATE TABLE`, totals and grouped/combined-filter reference queries.
   * `03-change-batch.sql`: bounded, deterministic insert with a mandatory separate collision check.
   * `expected-local.json`: local expected counts and decimal totals before/after; these are **not live results**.
3. Keep generated data/config and live evidence appropriately secured. The generator is pure Python; run local checks with `python -m unittest discover -s demos\power-bi -p "test_*.py"`.

The columns/types are: DimDate (`DateKey INT`, `Date DATE`, `CalendarYear INT`, `CalendarMonth INT`, `MonthName STRING`, `DayOfMonth INT`, `IsWeekend BOOLEAN`); DimProduct (`ProductKey INT`, `ProductName STRING`, `Category STRING`, `UnitPrice DECIMAL(12,2)`); DimCustomer (`CustomerKey INT`, `CustomerName STRING`, `Region STRING`, `Segment STRING`); FactSales (`SalesLineKey BIGINT`, dimension keys `INT`, `Quantity INT`, `UnitPrice DECIMAL(12,2)`, `SalesAmount DECIMAL(14,2)`). FactSales is one order line. DDL uses the shared schema metadata; all four primary keys and fact foreign keys are declared before publishing.

## Troubleshooting and limitations

* Permission/consent/XMLA/warehouse/home-tenant failure: record exact sanitized error and block. If the Microsoft Entra popup cannot open in the embedded Browser canvas, open the Databricks workspace in a regular browser session that permits popups, choose **Use with BI tools → Publish to Power BI → Connect to Microsoft Entra ID**, complete sign-in, and return to the flow. Do not substitute an undocumented publishing API. Do not alter tenant, capacity, identity, shared permissions or create infrastructure as a workaround.
* Missing or inactive relationship: capture pre-edit metadata and mark unmet/partial; documentation indicates multiple paths can yield inactive relationships. No live behavior is asserted here.
* Wrong mode or stale results: check per-table model storage mode, report query freshness, refresh status and credentials. Import needs a completed refresh; DirectQuery needs a new query and may encounter caching. A timeout is a failed visibility check, not permission to extend it.
* A schema or workspace name collision is not proof of ownership. Stop and choose a new name. `03-change-batch.sql` is not replay-safe and must be guarded as described.
* The expected values are local calculations, not proof of Databricks or Power BI behavior. Record actual observed evidence separately.
